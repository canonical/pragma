# withModal

`withModal` is a higher-order component: give it a trigger component and a function that returns a `<Modal>`, and it returns a new component that opens that modal when the trigger is clicked. It owns the wiring — the trigger's `onClick` opens the dialog, the header's X and Escape close it — and hands the modal's `close` to your function so a footer button can close it too.

```tsx
import {
  withModal,
  Modal,
  Button,
  type WithModalRender,
} from "@canonical/react-ds-global";

const maintenanceModal: WithModalRender = ({ close }) => (
  <Modal>
    <Modal.Header>Maintenance scheduled</Modal.Header>
    <Modal.Content>The service will restart at 02:00 UTC.</Modal.Content>
    <Modal.Footer>
      <Button importance="primary" onClick={close}>
        Got it
      </Button>
    </Modal.Footer>
  </Modal>
);

const MaintenanceButton = withModal(Button, maintenanceModal);

function Toolbar() {
  return (
    <MaintenanceButton importance="secondary">
      Maintenance notice
    </MaintenanceButton>
  );
}
```

## Define it at module scope

`withModal` returns a new component. Call it at module scope — not inside a render body — so its identity is stable across renders:

```tsx
// Good — built once, stable identity across renders.
const Saved = withModal(Button, savedModal);

function Bar() {
  return <Saved>Save</Saved>;
}
```

```tsx
// Avoid — a new component type every render remounts the subtree,
// and an open modal would close on every parent re-render.
function Bar() {
  const Saved = withModal(Button, savedModal); // don't
  return <Saved>Save</Saved>;
}
```

That is also why the content is static: the function you hand over runs on every render of the trigger, but defined at module scope it can only see module-level values. If the modal must show data from the parent — a different `userName` depending on which user is selected — skip this HOC: compose [`Modal`](?path=/docs/patterns-modal--docs) directly and drive it through its `ref`.

The returned component's `displayName` is `` `withModal(${Component.displayName || Component.name || "Component"})` `` — so `withModal(Button, …)` appears in React DevTools as **`withModal(Button)`**.

## How it closes

The header's X button and Escape always work. Add `closeOnBackdropClick` to the returned modal element and a backdrop click works too. **Footer buttons can only close the modal** — that is the one and only action this HOC provides, through the `close` it hands your function. If an action needs to do more — save data, open another modal, close conditionally — compose `Modal` directly and drive it through its `ref`.

## The trigger does not have to be a Button

Any component that accepts `onClick` and forwards it to the clickable element at its root works, because the HOC hooks the open handler onto the trigger itself. Here a styled `<div>` is that root, so the modal opens when it is clicked:

## Accessibility

A modal composed without a header has no title to name the dialog, so it must carry its own `aria-label`. With a header, the title names the dialog automatically through `aria-labelledby`.
