# Connect a GraphQL API

A collection backed by a GraphQL endpoint uses the application's own Relay environment through `createRelaySource`. DataViews adds no cache of its own: Relay's store stays the only cache, and each request retains its operation, delivers a page already in the store at once, fetches it, and follows every later change to the store.

The stories on this page are answered by a mock endpoint, served by Mock Service Worker. It stands in for a real endpoint so the stories can show what a local array cannot; it is not evidence about any real API.

## Declare what the endpoint runs

The declaration is the whole offer. Every part reads it: Filters offers a control only for what is declared, a header sorts only a declared field, and anything else is refused before a request is sent. This endpoint filters the statuses a machine is any or none of, bounds cores, looks for text the host name, the region and the owner contain and text the host name and the owner start with, searches, orders by one term, and pages forward by cursor with no counts at all. An endpoint that counts nothing leaves `counts` out: the pagination bar then says which items are on screen and never out of how many.

```tsx
import {
  createRelaySource,
  declareCapabilities,
  readSlice,
} from "@canonical/dataviews-core";
import { createOperationDescriptor } from "relay-runtime";
import MachinesQuery from "./__generated__/MachinesQuery.graphql.js";
import { machineCollection } from "./machines.js";
import { environment } from "./relay.js";

const capabilities = declareCapabilities(machineCollection, {
  filter: {
    status: ["isAny", "isNone"],
    cores: ["gte", "lte"],
    name: ["contains", "startsWith"],
    region: ["contains"],
    owner: ["contains", "startsWith"],
  },
  search: ["name", "owner"],
  sort: {
    fields: ["name", "status", "cores", "region", "owner"],
    terms: 1,
    tiebreak: "opaque",
  },
  pagination: { kind: "cursor", backward: false, durable: false },
  facets: ["status", "cores"],
});
```

## Map a request onto the endpoint

The query pages by its own `first` and `after` arguments, not through `@connection`, which would merge its pages. `readSlice` reads the request by field, so the variables are built by name: a field whose kind accepts several operators reads as a record of them — a status filter as the sets it is any and none of, a text filter as the text it contains and starts with.

```tsx
const source = createRelaySource({
  capabilities,
  environment,
  operation: ({ slice, first, after, facets }) => {
    const { filters, search, sort } = readSlice(machineCollection, slice);
    return createOperationDescriptor(MachinesQuery, {
      first,
      after,
      where: {
        status:
          filters.status?.isAny === undefined ? null : [...filters.status.isAny],
        statusIsNone:
          filters.status?.isNone === undefined
            ? null
            : [...filters.status.isNone],
        coresGte: filters.cores?.gte ?? null,
        coresLte: filters.cores?.lte ?? null,
        nameContains: filters.name?.contains ?? null,
        nameStartsWith: filters.name?.startsWith ?? null,
        regionContains: filters.region?.contains ?? null,
        ownerContains: filters.owner?.contains ?? null,
        ownerStartsWith: filters.owner?.startsWith ?? null,
        search,
      },
      orderBy: sort.map(({ field, direction }) => ({
        field,
        direction: direction === "asc" ? "ASC" : "DESC",
      })),
      facets: [...facets],
    });
  },
  connection: (data) => data.machines,
});
```

The provider and the parts are built over it as over any other source. Asked for facets — `createDataViewsProvider({ collection, source, facets: ["status", "cores"] })` — every request names them, and the operation selects them.

## Counts and ranges from the endpoint

The `facets` variable asks the connection for the machines holding each status and for the least and greatest number of cores, computed over every machine the query matches rather than the page Relay holds. A field's own restriction is left out of its own facet, so the other statuses keep their counts while one is applied. Filters shows each count beside its option and each end of the range beside its bound.

## Text a field contains or starts with

`nameContains` asks for the hosts whose name holds the text, and `nameStartsWith` for those whose name begins with it, compared case-insensitively. The text is literal, so `50%` never matches `5050`. The owner has both text inputs here, because this endpoint declares both operators on it; the region only the one for text it contains.

## When the endpoint cannot answer

When the endpoint fails, the reason it gives stands in place of the rows. When a later page fails, the rows already shown stay, marked as no longer answering the query.

The reason is whatever the environment's network throws, so the network reads the answer rather than trusting it. An answer whose data holds something is passed on with any errors beside it — a partial answer, which Relay stores — and one whose data holds nothing fails in the endpoint's own words:

```tsx
import { Environment, Network, RecordSource, Store } from "relay-runtime";

export const environment = new Environment({
  network: Network.create(async (request, variables) => {
    const response = await fetch("/graphql", {
      method: "POST",
      headers: { "content-type": "application/json" },
      body: JSON.stringify({
        query: request.text,
        operationName: request.name,
        variables,
      }),
    });
    const body = await response.json().catch(() => null);
    if (typeof body !== "object" || body === null || Array.isArray(body)) {
      throw new Error(
        response.ok
          ? "the endpoint answered without a JSON object"
          : response.statusText || `the endpoint answered ${response.status}`,
      );
    }
    const { data } = body;
    // Data that holds nothing — a failed nullable root field is answered as
    // null beside its error — is no page, so it fails like no data at all.
    if (
      typeof data === "object" &&
      data !== null &&
      Object.values(data).some((value) => value !== null && value !== undefined)
    ) {
      return body;
    }
    const [error] = Array.isArray(body.errors) ? body.errors : [];
    if (error !== undefined) {
      // A failure's message is what the table shows beside the rows.
      throw new Error(
        typeof error?.message === "string"
          ? error.message
          : "the endpoint answered with an error it did not describe",
      );
    }
    throw new Error(
      response.ok
        ? "the endpoint answered without data"
        : response.statusText || `the endpoint answered ${response.status}`,
    );
  }),
  store: new Store(new RecordSource()),
});
```

## A request the endpoint cannot run
