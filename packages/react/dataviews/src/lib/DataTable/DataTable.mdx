# DataTable recipes

`DataTable` renders the rows of one collection and nothing else: it does not fetch, own the URL or decide where views persist. A provider owns the collection's query, result and selection; a source binding feeds it; the table reads it. Each recipe below is the smallest complete code for one job, followed by the live story that shows it.

The table is dense wherever it sits: its root carries the design system's `.dense` class, and its rows and cells take their height and padding from the density channel of `@canonical/styles`, so load that stylesheet on the page. Its sort chevrons and checkbox marks are `@canonical/ds-assets` icons, which the page serves at `/icons`, as for every other design-system icon.

## A table over a provider

Build the provider once and keep it for the table's lifetime. The binding is different: it subscribes to the provider, so it belongs in an effect that disposes it — a render React throws away must never leave a subscription behind. Ask for the first page only while nothing has been asked yet: StrictMode runs the effect twice in development, and the second run finds the first page already requested. From then on every sort, search or page change issues its own request. The source declares every field it can filter and sort, and the provider is told that declaration through `capabilities`, so the table and the filters offer only what the source can run.

```tsx
import {
  createArraySource,
  createDataViewsProvider,
  createSourceBinding,
} from "@canonical/dataviews-core";
import { DataTable, type DataTableColumn } from "@canonical/dataviews-react";
import { useEffect, useState } from "react";
import { machineSchema, machines } from "./machines.js";

const columns: readonly DataTableColumn[] = [
  { id: "name", header: "Host" },
  { id: "status", header: "Status" },
  { id: "owner", header: "Owner" },
];

export function Machines() {
  const [source] = useState(() =>
    createArraySource({ rows: machines, fields: ["name", "status", "cores"] }),
  );
  const [provider] = useState(() =>
    createDataViewsProvider({
      schema: machineSchema,
      capabilities: source.capabilities,
    }),
  );
  useEffect(() => {
    const binding = createSourceBinding({ host: provider, adapter: source });
    if (provider.result.get().result.status === "idle") {
      provider.refresh();
    }
    return binding.dispose;
  }, [provider, source]);
  return <DataTable provider={provider} columns={columns} label="Machines" />;
}
```

Every column shows the record field its id names; `field` names a different one. Primitive values render as text, and anything else needs a cell renderer.

## Columns and sizing

A column is `fixed` — it keeps exactly its width — or `flex`: it takes at least its `minPx`, at most its `maxPx`, and a share of whatever is left by `weight`. The solver reserves every fixed width and every minimum first, then shares the rest; a column that reaches its maximum hands its excess back to the others. When even the reservations do not fit, nothing is squeezed: the table scrolls. The one exception is the last column, which takes whatever width the columns before it leave — past its own maximum or fixed width when there is room to spare — so the table never ends in a gap.

```tsx
import { createDataViewsProvider } from "@canonical/dataviews-core";
import { DataTable, type DataTableColumn } from "@canonical/dataviews-react";
import { machineSchema, source } from "./machines.js";

const provider = createDataViewsProvider({
  schema: machineSchema,
  capabilities: source.capabilities,
});

const columns: readonly DataTableColumn[] = [
  { id: "name", header: "Host", sizing: { kind: "flex", weight: 2, minPx: 160 } },
  { id: "status", header: "Status", sizing: { kind: "fixed", px: 112 } },
  { id: "region", header: "Region", sizing: { kind: "flex", weight: 1, minPx: 96, maxPx: 144 } },
  { id: "cores", header: "Cores", sizing: { kind: "fixed", px: 80 } },
  { id: "owner", header: "Owner", sizing: { kind: "flex", weight: 1, minPx: 96 } },
];

<DataTable provider={provider} columns={columns} label="Machines" />;
```

## Sorting

Mark a column `sortable` only when its source declares that field sortable, and pass the source's declaration to the provider as `capabilities`: the table reads it, and a sortable column on a provider created without it throws. A source refuses a query carrying a sort term it never declared, so a heading offering that sort would be a control that does nothing. The heading cycles ascending, descending, then back to the source's own order, and reports it through `aria-sort`. An ordered heading shows a chevron — up for ascending, down for descending — and an unordered one shows none; the chevron repeats the order for the eye, and `aria-sort` is what carries it to assistive technology.

```tsx
import { createDataViewsProvider } from "@canonical/dataviews-core";
import { DataTable, type DataTableColumn } from "@canonical/dataviews-react";
import { machineSchema, source } from "./machines.js";

const provider = createDataViewsProvider({
  schema: machineSchema,
  capabilities: source.capabilities,
});

const columns: readonly DataTableColumn[] = [
  { id: "name", header: "Host", sortable: true },
  { id: "status", header: "Status", sortable: true },
  { id: "region", header: "Region" },
  { id: "cores", header: "Cores", sortable: true },
  { id: "owner", header: "Owner" },
];

<DataTable provider={provider} columns={columns} label="Machines" />;
```

## Selection

`selectable` adds a leading 32px column of the design system's `CheckboxInput`, backed by the provider's selection; the column's width is the stylesheet's, and the data columns share what it leaves. Name each record with `rowLabel`, so a checkbox says which machine it selects rather than which position it holds. The header checkbox acts on the rows the reader can see, and leaves a selection made on another page alone.

```tsx
import { createDataViewsProvider } from "@canonical/dataviews-core";
import { DataTable, type DataTableColumn } from "@canonical/dataviews-react";
import { machineSchema, source } from "./machines.js";

const provider = createDataViewsProvider({
  schema: machineSchema,
  capabilities: source.capabilities,
});

const columns: readonly DataTableColumn[] = [
  { id: "name", header: "Host" },
  { id: "status", header: "Status" },
  { id: "owner", header: "Owner" },
];

<DataTable
  provider={provider}
  columns={columns}
  label="Machines"
  selectable
  rowLabel={(row) => String(row.name)}
/>;
```

## Resizing and its limits

`resizable` puts a control on a column's trailing edge, driven by the pointer or the keyboard — arrow keys step the edge, Escape abandons a drag. Every resize is held to the column's declared `minPx` and `maxPx`, however often it has been resized, and a column widened past the container scrolls the table so the edge being moved stays in view.

The last column never gets a control, even when it is declared `resizable`: its trailing edge is the table's own edge, with nothing beyond it to resize against. It takes whatever width the others leave instead. To give two tables on one provider the same user arrangement, pass them one shared `presentation`.

```tsx
import { createDataViewsProvider } from "@canonical/dataviews-core";
import { DataTable, type DataTableColumn } from "@canonical/dataviews-react";
import { machineSchema, source } from "./machines.js";

const provider = createDataViewsProvider({
  schema: machineSchema,
  capabilities: source.capabilities,
});

const columns: readonly DataTableColumn[] = [
  { id: "name", header: "Host", resizable: true, sizing: { kind: "flex", weight: 1, minPx: 120, maxPx: 320 } },
  { id: "region", header: "Region", resizable: true, sizing: { kind: "flex", weight: 1, minPx: 96, maxPx: 160 } },
  { id: "status", header: "Status", sizing: { kind: "fixed", px: 112 } },
  { id: "owner", header: "Owner", sizing: { kind: "flex", weight: 1, minPx: 96 } },
];

<DataTable provider={provider} columns={columns} label="Machines" />;
```

## A cell that reads its own scope

A column's `cell` renderer runs inside its cell's scope, so it can read the row's channels with `useDataViewsCell` — the whole record, another field, or the row's selection — without the table handing every cell a copy of the record. It re-renders when those channels change, and nothing else does.

```tsx
import { createDataViewsProvider } from "@canonical/dataviews-core";
import {
  DataTable,
  type DataTableCellProps,
  type DataTableColumn,
  useDataViewsCell,
  useDataViewsValue,
} from "@canonical/dataviews-react";
import { type Machine, machineSchema } from "./machines.js";

const provider = createDataViewsProvider({
  schema: machineSchema,
  capabilities: source.capabilities,
});

function HostCell({ value }: DataTableCellProps) {
  const { row, selected } = useDataViewsCell(provider);
  // The cell scope carries the record as the source delivered it.
  const { owner } = useDataViewsValue(row) as Machine;
  const isSelected = useDataViewsValue(selected);
  return (
    <span
      style={{
        fontWeight: isSelected
          ? "var(--typography-text-primary-bold-font-weight)"
          : undefined,
      }}
    >
      {String(value)}
      <span style={{ color: "var(--color-text-muted)" }}> ({owner})</span>
    </span>
  );
}

const columns: readonly DataTableColumn[] = [
  { id: "name", header: "Host", cell: HostCell },
  { id: "status", header: "Status" },
];

<DataTable
  provider={provider}
  columns={columns}
  label="Machines"
  selectable
  rowLabel={(row) => String(row.name)}
/>;
```

## The four outcomes

A table with no rows says why, and the four reasons stay distinct: nothing has arrived yet, the read failed, the collection is empty, or the query matched nothing. They call for different responses from the reader — wait, retry, add something, change the query — so they are never collapsed into one message. `renderStatus` replaces the default text with your own words; the stories below show the defaults.

```tsx
import { createDataViewsProvider } from "@canonical/dataviews-core";
import {
  DataTable,
  type DataTableColumn,
  type DataTableStatus,
} from "@canonical/dataviews-react";
import { machineSchema, source } from "./machines.js";

const provider = createDataViewsProvider({
  schema: machineSchema,
  capabilities: source.capabilities,
});

const columns: readonly DataTableColumn[] = [
  { id: "name", header: "Host" },
  { id: "status", header: "Status" },
];

const statusText = (status: DataTableStatus): string => {
  switch (status.kind) {
    case "loading":
      return "Fetching machines…";
    case "error":
      return `Could not read machines: ${status.reason}`;
    case "no-data":
      return "No machines are enrolled yet.";
    case "no-results":
      return "No machines match this search.";
  }
};

<DataTable
  provider={provider}
  columns={columns}
  label="Machines"
  renderStatus={statusText}
/>;
```
